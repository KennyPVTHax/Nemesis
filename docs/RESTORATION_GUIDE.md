# Restoration and review guide

Checkout this PR branch and verify docs/BACKEND_EXPORT_SHA256SUMS.txt from repository root with sha256sum -c. docs/IMPORT_MANIFEST.json records each recovered source file hash, exact new location and private/generated exclusions. The original backend archive and all workspace checkpoints remain outside the public repository; they are not a durable offsite backup and must be secured by the owner.

The hybrid Android root is android/; its native Gradle project remains android/android/ to preserve Capacitor build paths. Run npm ci, npm run build, npm test, npx cap sync android there. Then run ./gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug from android/android with JDK21 and SDK35. cap sync regenerates excluded native web assets/Cordova configuration. Do not regenerate src/generated from unreviewed HTML. Branding, application code, native resources and four tabs are unchanged.

The earlier source in legacy/preserved-features/phase1-ui is actual extracted Android UI from a checkpoint, not the independent original website. No full website/child Android source exists in the recovered inputs. Do not claim those projects are backed up or fabricate them. Historical mock credential files remain privately excluded and must never become production fallback code. No unreviewed private-message/financial-secret monitoring code is included in this public import.

Backend source is preserved, not automatically launched. Production paths, credentials and account data are intentionally missing. Recover deployment configuration separately under restricted access; no live VPS changes belong in this PR. Review the OTP rollback defect before deploying another instance. Use only temporary databases and intercepted Telegram calls for tests. Firebase inventory tests do not verify actual project Rules. Disabled dashboard/APK adapters remain disconnected through explicit unavailable adapters; comments or hidden UI are not authorization boundaries.

Before restoring any inactive feature: recover its real source, inspect consent/authorization and credential handling, define explicit build/runtime exclusion, obtain any backend-change approval, test with isolated accounts/projects, update FEATURE_STATUS, and submit a separate PR. Never deploy/import live databases, signing keys, bot credentials or customer records into Git history. No merge or deployment is automatic.
