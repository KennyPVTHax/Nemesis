# Public import security review

The public upload contains only inspected source/resources/configuration examples. No bot tokens, private API/signing keys, password hashes, SQLite databases, environment secrets, customer records, captured messages, native APK binaries, deployment logs or unreviewed monitoring functionality are included. Source literals referencing credential field names and production filesystem paths are interfaces/configuration references, not actual credential material. Imported backend bytes did not require redaction. Runtime and signing material remain outside Git.

Review covered original archive filenames and all ten modules, current Android source and extracted UI, selected actual legacy UI, staged filenames/content, binary asset types, and every reachable commit on both existing branches plus new import commits. Gitleaks 8.24.3 default detectors found three generic-api-key matches in docs/phase2/BASELINE.json. Manual examination confirmed each is exactly a 64-character hexadecimal provenance hash; the JSON is a source-file SHA-256 map. They are retained to preserve verifiability. No suppression rules are enabled and no secret values are printed in public reports. A second indexed-source audit rejects credential/key/hash patterns and runtime filenames and checks exact imported file hashes.

Historical mock-login files with fixed development credentials are retained only in the private workspace/checkpoints, with hashes and exclusion reasons in IMPORT_MANIFEST.json. Generated native web assets and Cordova configuration are build outputs regenerated by cap sync; no original feature implementation is lost by those build exclusions. The earlier unfinished backend-dev directory, runtime data, SDK/JDK/dependency installations and original archives were not imported. Native resource images, fonts/licenses and Gradle wrapper are reviewed build assets.

The original raw monitoring website and child-device project are unavailable. The published legacy snapshot contains only the already extracted, disconnected UI, not SMS interception, unrestricted sending, private-message collection or financial-secret extraction. No feature is activated by this migration. Existing disconnected handlers remain explicit and backend authorization remains required. UI visibility/comments are not access-control mechanisms.

Open blocker for a separate reviewed fix: failed OTP attempts roll back in the exported auth_api.verify transaction. Preserved as-is and covered by strict xfail; not repaired on the VPS. Full Firebase Rules, deployment configuration and original production dependency lock are absent. These limits prevent claiming complete production hardening or a complete backup of missing projects. No history rewrite, force push, service operation, deployment or automatic merge was performed.

A temporary local dependency symlink was accidentally indexed during build preparation and removed in a follow-up housekeeping commit before publication. Its historical blob contains only a workspace directory path, not dependency files, credentials or customer data. History is retained without rewriting; no dependency symlink is present in the delivered tree.
